## 公共对象和入口

| 对象或接口 | 供调用者使用的契约 |
|---|---|
| `PreparedNetwork.from_config(load_config(...))` | 从项目根目录解析 P0 正式清单，核对道路、网络 manifest、道路及航空审计哈希。核对方向策略、两种速度、班距及全图站点映射，返回 `road` 和 `air`。 |
| `RoadRouter.shortest_time_s(u,v)`、`shortest_path_edges(u,v)` | 道路节点使用 P0 整数 ID。前者返回 Decimal 秒，后者返回有序的不可变物理边。不可达抛出 `UnreachableRoad`，同一已知节点返回 0 秒和空路径。可通过 `parallel_edges` 查看两点间的全部有向边。 |
| `AirNetwork.routes`、`station_nodes`、`flight(route_id,index)` | 提供有向静态航线、名义飞行时间和站点对应的全图道路节点。固定航班 ID 为航线 ID 加班次索引。起飞时间为相位加索引乘班距，每个实例独立持有容量和预订。 |
| `Request`、`Plan`、`Leg`、`WalkLink` | 请求 ID 为稳定字符串，可将 P0 原记录 ID 转成十进制字符串。请求保留原始提交秒、原始及映射 OD、人数、cohort、两种容忍时间。方案以请求 ID 和方案 ID 识别，段 ID 在方案内唯一。正式段可携带 EP、LP、LD，辅助步行带距离和速度。 |
| `Task`、`FlightInstance` | 任务 ID 将带长度的请求 ID、段 ID 和任务种类组合。车辆接送各一项，航班一项，步行有开始和结束事件。任务保存直接前序、资源、状态和执行时刻。航班在起飞时统一验证全部已锁座乘客，在降落时完成该航段。 |
| `VehicleState` | 车辆 ID、容量、载客请求和人数、当前节点或有向边、位置、精确起止时刻、剩余路径和预约动作。边上的位置按 P0 经纬度端点线性插值。在途乘客的位置可由请求状态、当前段和绑定运力确定。 |
| `Simulator.schedule_arrival(id, at, loader)`、`advance_to(t)` | 事件引擎仅在提交秒调用请求载入器。可以跨过多个批次推进，也可在任意非负整数秒检查物理状态。请求释放时复核静态直达耗时，车辆段接受时复核其名义耗时。 |
| `snapshot()`、`batch_snapshot()` | 返回冻结对象和只读映射，保存时刻、状态版本及路网版本。前者支持物理观测，后者检查批次边界。正式默认每 10 秒允许新决策。`request_types(previous_batch_time)` 区分新到达、积压和已接受未完成，排除终态请求。 |
| `accept(id, plan, bindings)`、`CandidateRoute`、`commit_route(candidate)` | 接受请求时一并冻结整条方案、各段车辆/航班和座位。单车候选只带快照版本、车辆、当前边之后的目的地和未来动作。提交前检查版本、道路、重复/遗漏任务、已执行前缀、容量和已知接驳时限。 |
| `BatchSnapshot.road_arrival(...)`、`remaining_route(...)` | 前者从节点或当前冻结边终点预测改线后的最早到达秒。后者取得本批次剩余单车计划。没有替代决策时，原计划继续执行。 |

请求状态为 WAITING、ACCEPTED、ON_VEHICLE、ON_FLIGHT、WALKING、COMPLETED、EXPIRED_UNSERVED。任务状态为 PENDING、ACTIVE、COMPLETED。航班状态为 SCHEDULED、AIRBORNE、LANDED。行驶中的道路边完成事件独立于可替换的路线版本。事件序号在单次运行中唯一。

## 唯一时间规则

道路长度为米，速度为米/秒，连续行驶耗时为秒。将 P0 JSON 中的十进制秒按其原始精度读取。每条边的物理到达时刻等于连续运动起点加上截至该边的全部边权之和，记为 `a_k`。执行秒为 **`event_second(a_k) = ceil(a_k)`**。最短路使用精确尺度的整数边权，规划与执行通过 `exact_add` 累计。道路历史同时保留整数执行秒和精确到边时刻。实际停等、上下客或新步行开始时，以相应整数事件秒为新起点。目标时长在评分接口转换为浮点分钟。

人工图从第 0 秒连续走三条 0.4 秒边，其物理到达为 0.4、0.8、1.2，执行秒为 1、1、2。第 1 秒时第三条边已走一半。此时将第三条边后的路线改为一条 0.75 秒边，第四次物理到达为 1.95，执行秒仍为 2。预测和实际都继承了 1.2 秒的当前边终点。

时间窗保留原始精度，整数事件时刻须小于或等于原始上限。例如，提交时刻为 0、直达 1.2 秒、容忍 420 秒，终达上限是 421.2 秒，最后可执行秒为 421。该实现选择在小数截止附近可能收紧不足 1 秒。逾期检查在第一个严格超过截止的整数秒运行。

## 同刻事件优先级

队列键为 `(执行秒, 优先级, 入队序号)`，数值较小者先执行。同刻因果事件在其前序成功后才能入队。固定输入顺序可重放平局。调度取得快照前排空截至该时刻的既有事件，决策产生的同秒动作属于随后一次执行。外部计算耗时不会推进时钟。

| 优先级 | 事件 | 边界语义 |
|---:|---|---|
| 0 | EDGE_END | 完成当前有向边，沿剩余路径继承精确小数秒 |
| 1 | LAND | 完成已登机乘客的飞行，释放乘客到达位置 |
| 2 | WALK_END | 乘客抵达步行终点，可以接驳 |
| 3 | DROPOFF | 下客并释放整组人数占用的车辆座位 |
| 4 | WALK_START | 仅已接受且前序完成的乘客可以起步 |
| 5 | PICKUP | 核对乘客就绪、车辆位置、资源承诺、时间窗及容量 |
| 6 | DEPART | 固定航班起飞，同秒已到站且已订座者可登机 |
| 7 | DRIVE | 按预约发车，允许同秒先上下客再驶离 |
| 8 | ARRIVAL | 释放新请求，核验原始时间和静态直达耗时 |
| 9、10 | EXPIRE、EXPIRE_FINAL | 分别处理首次登乘和最终送达截止 |
| 全部处理后 | 批次快照 | 第 18 秒提出的请求最早在第 20 秒正式决策，已于第 18 秒执行的接客保留原时间戳 |

## 剩余风险与 P2 接口

单请求接受与单车路线替换分别具备原子性。未来 M4 仍需在同一份快照上联验整批车辆、航班、服务链，再整体提交。P1 允许分步构造单车预约。尚未排定的后续动作只有时间下界，接受后失约会触发 FAILED。历史和快照在内存中保留。长期运行的流式输出、内存规模及正式负载性能留待后续授权验证。重复实际停等或服务交接时，整数时刻对每个新起点的影响须在后续评估中保留。

M1 可以直接使用 `road.shortest_time_s`、`air.routes`、`air.station_nodes` 和 Request/Plan/Leg/WalkLink。生成抽象道路连接时捕获 `UnreachableRoad`，生成静态航段时读取 `nominal_time_s`。P1 接口对 P2 开发没有已知阻塞。P2 尚待独立授权。
