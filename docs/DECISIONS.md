# 最终设计决策登记（D001–D015）

**状态：** D001–D014 已经用户逐项确认；D015 的模块结构、阶段开发、手动运行和输出方式已确认。
本文件**替代**旧版 `UAM_Reproduction_Design_v0.1.md`，不是新一轮自由设计讨论。
凡标记【论文】直接来自论文；【推断】是为了协调不同章节得出的解释；【已批准补充】是用户同意的工程实施选择。
复核论文细节见 `references/paper.pdf` 与 `docs/PAPER_TRACEABILITY.md`。

## D001 — M1 与理论旅行时间

- 【论文】M1 为每个请求寻找最多 K 条满足请求自身条件的 Top-K 可替代服务方案；M3、M4 才确定现实车辆和航班资源。
- 【已批准补充】M1 采用静态名义旅行时长；道路边为有向道路最短旅行时间，航空边为固定飞行时长；**不在 M1 把实际航班排队/等待时间提前计入航线边**。
- 【已批准补充】实际航班时刻、席位和路上可行性交 M3/M4。
- 【论文/推断】地面换乘点、请求 O/D 之间只要有道路路径便有抽象地面运输边，方向与有向最短路径一致。
- 原始请求 \(t_i^r\)，首次接客截止 \(t_i^r+\Delta_i\)，最终到达截止
  \(D_i=t_i^r+st(G^r,o_i,d_i)+\alpha_i\)，不使用历史出租车行程末时刻。

## D002 — 多行程窗口与时间表示

- 【已批准】使用公式：\(EP_1=t_i^r\)；\(EP_j=EP_{j-1}+\ell_{j-1}\)；
  \(LP_1=t_i^r+\Delta_i\)；\(LP_j=LD_{j-1}\)；
  \(LD_m=D_i\)；\(LD_j=LD_{j+1}-\ell_{j+1}\)（向后递推时用**下一段**时长）。
- 上述是对论文式 (1c) 可疑索引的已确认工程解释；必须在小图测试中证明上下界与实际顺序一致。
- 跨段实际等待全部计入最终请求总出行时间；同一处起降场地空连接时间暂定 `transfer_time_s=0`，不能跨地点免费移动。
- 事件时间统一以秒为基本单位；道路权重允许精确小数，最终要采用统一的确定性量化约定，**不能逐道路边粗暴四舍五入造成累计误差**。具体量化实现以测试门槛审计，不擅自混用。

## D003 — M4 完整物理解码

- 车辆从当前有效位置/可用时刻前往任务点，接客发生在
  `max(vehicle_arrival, passenger_ready)`，允许车提前到达等待。
- 送客任务必须考虑真实车辆顺序、两次任务间最短道路行驶时间、载客人数和乘客就绪时间，不可仅把各个乘客 OD 最短路相加。
- 同车拼车的完整任务序列、乘客跨车/航班/步行衔接、固定航班出发与到达、历史时限和承诺共同参与可行性判断。
- 共享航班双向关系是容量关联而非时间互等约束；真正的因果循环或不可能等待必须拒绝。
- 先编写完整解码作为测试参考，随后实现论文任务图弱连通分解；独立验证不能只是读取解码器返回的布尔值。

## D004 — 滚动调度状态/事件

- 每 10 秒一次优化；内部是精确时间戳的离散事件模型。`advance_to(batch_time)` 在批次前按发生时间逐个回放过去 10 秒内的事件。
- 车辆连续在有向边上运动；当前边走完之前不可重新规划方向，新方案从边终点及真实到达时间接续。
- 已执行任务永不回滚；已接受 Type3 请求的整条方案、运力/航班承诺不可更改，但尚未执行的地面任务可在不违反承诺下重新排序。
- 当前快照只读；候选计算不修改真实状态；最终计划采用原子提交。路线版本使过时未来事件无效。
- 对已接受航班保留预订席位，新请求只竞争未被预订的容量。
- 记录前轮合法剩余计划作为安全基础解；搜索失败或超时可退回它。
- 【用户明确决定】计算耗时**不增加模拟时间**，在时刻 t 即时生效；墙钟/CPU 仅用于性能记录/求解预算。
- 不允许虚构尚未到达的请求已经被接受或上车。

## D005 — 初始解、删除修复、目标

- 论文随机初始化先固定 Type3，后对 Type1/2 选择最短候选方案并随机选择各段资源，随机生成重复请求编号序列。
- 不可行 Type1/2：删除其**整个当前候选分配**（所有行程、资源和任务），重新解码；这不意味着将真实待满足请求永久删除。
- 不可行 Type3：整份候选方案作废；**绝不删除已接受请求**。
- 安全基础解 S0 在本批次当前快照上重新评分；随机初始化候选 S1 可作为 HALNS 的 `current`，`best` 取当批 S0/S1 合法得分高者。
- 当前解允许较差合法值，`best` 单调不降；最后返回最高分合法解。
- 【论文+批准解释】\(f_1=\delta\times\) 当前批次候选中得到完整运输服务分配的请求数（包含仍有任务的 Type3）；\(f_2=\sum_i(t^{final}_{drop,i}-t_i^r)\)。
  \(v=\beta f_1-(1-\beta)f_2\)。注意出行时间在目标函数按**浮点分钟**计算。
- 全局服务率按唯一评价请求计数，不能累加批次 \(f_1\)。不同批次 v 不可直接比较。

## D006 — 两层编码与独立分量

- 搜索层保留论文重复请求 ID 的第二层编码；当前位置某请求的第 n 次出现对应其**尚待执行的第 n 个**实际任务。已完成前缀不重建。
- 解码层建立稳定、唯一的实际 Task ID，以支撑事件执行、承诺和审计。
- 任务关联网络包含同车执行顺序、乘客跨段因果依赖、同航班容量共享；分解用弱连通分量。
- 共享航班的双向关联**不是**互相等待的时间先后边。
- 改变方案/运力必须重建受影响关联和分量；分量内序列算子可局部处理。
- 正式默认 `partitioned`，完整解码只用于开发对照和 noD 消融；两者对固定有效候选必须一致。
- noD 同时取消分量级搜索算子范围，而非仅多做一次全量解码。

## D007 — HALNS 算子与控制

- 七算子：`p_exchange,v_exchange,restart,insert,cut,swap,reverse`。
- 方案/运力交换默认 `m=1` 可配置；`p_exchange` 任务重复 ID 数量随新方案变化，保留未选中请求的相对顺序；随机插入/删除位置受统一随机数生成器控制；解码再次验证。
- `restart` 从该批次完整**仍有效** Type1/2 请求重建（包括先前在某候选解中被删除的请求），Type3 仍固定原方案/资源。
- 第一个批次算子初始评分相等且为正，后续批次继承评分；\(\theta=0.1,\psi=0.4,\omega=0.02\)；轮盘赌正数下限。
- 标准最大化模拟退火：改善当前解必接受；较差合法解概率
  \(\exp((v_{\rm new}-v_{\rm current})/T)\)；不可行解不得接受；`best` 保留最高分。
- 初温 `T0=70*|R|`；按论文 Algorithm 4 每次内层迭代降温 `T*=0.7`。
- 外层最多 `2*|R|`，内层 `25`；墙钟时间预算与迭代双上限，先达到即停止，返回 `best`；支持 10s/30s 可配置。
- \(\beta=.7,\delta=100\)，目标时间单位浮点分钟、不提前舍入；参数的量纲与模拟退火分数差一致。
- 论文 §5.3.5 “first four operators” 对 Type3 的限制与 Table 3 分类存在文字不够清楚之处；**禁止**任何算子更改 Type3 的承诺方案/资源。`insert` 对 Type3 任务默认不选为直接扰动目标；其余任务序列操作可以在完整因果/冻结验证后改变未执行顺序。将此解释在测试与偏差登记中保留。

## D008 — M1 Pulse / Top-K

- 请求进入系统时计算一次 K 个候选方案并按请求缓存；静态路网配置变化时缓存失效。
- K=5，最多 3 段正式运输行程，换乘次数<=2。
- 反向 Pulse：时间下界剪枝、换乘数剪枝、已有 K 个候选的最差成本剪枝，按论文概念。
- Algorithm 2 的候选维护逻辑必须真正替换**当前耗时最长**方案，而不是未排序列表中第一个更慢方案；确定性等成本规则。
- 抽象有向道路连接、静态航线；重复结构签名仅做轻量检查并优先诊断重复网络边。
- **15 分钟相对最短路径过滤**：仅保留接口，不实现、不开启。
- 微型路网完全穷举合法简单路径，对比 Pulse Top-K；未找到 K 个则按实际数量返回。
- M1 的名义可行不代表 M3/M4 可实际分配。

## D009 — M3 候选资源

- 每批从真实车辆位置（包括边中）建立 R-tree；按论文可达圆的**外接方框**检索，直线距离升序 + ID 稳定排序。
- 最多 `2*C_vehicle` 辆：四座车默认 8 辆（可配置）。
- 目前满载或空座小于请求人数的车辆**不在 M3 按当前空座筛掉**：它可能在接客前释放座位；最终 M4 严格检查实际接客时的容量。
- 真实总容量小于请求乘客人数的车辆可以安全排除。统计截断命中率、满载名额占用及实际选用率。
- Type3 固定承诺资源绕过 M3 普通候选上限，不参与重新竞争。
- 航班按起终点、起降窗口、当前剩余席位筛选；M4 负责联合新请求占用的最终容量。
- 使用稀疏候选资源映射，语义等价论文 LS；每批更新，禁止复用过时车辆/航班状态。
- T07a/b：符合普通空间候选且未截断的满载车不因当前满载被删除；仅在接客前实际释放足够座位时 M4 可接受。

## D010 — M5 再平衡

- 1km 网格，需求=本批 M4 后仍有效未满足**唯一请求数**，供给=真正可参加再平衡的空闲车数。
- Gurobi 解决式(25)–(31) 三类供需不均衡整数运输模型，网格间成本是中心点球面距离。
- 按输出整数流 x_ij 选择具体车辆，行驶目标为目标网格附近可达道路节点；实际轨迹按有向道路最短时间。
- x_ii 表示保留同网格，不移动。再平衡不直接接受请求。
- 正在再平衡的空车可被 M3/M4 抢占用于乘客服务，但必须先完成当前道路边；在再平衡未完成期间不反复参加 M5 目的地重选。
- M5 无可行解/失败时不损害已提交的 M4 乘客调度。
- 【用户最终决定】10/30 秒预算**只限制 M4**，M5 不预留时间、不使用该预算；分别统计 M4 耗时及整批耗时。不能声称 M4 达标等于整批达标。

## D011 — 网络、映射、步行、航班

- 使用 OSM 有向车辆路网；审计弱/强连通、优先考虑最大强连通分量，但**删减前须展示覆盖率和请求/站点映射影响**，不能为了图规模凑论文 6843/12601 强删边。
- 【P0 审计后批准】正式采用完整 Manhattan 行政区有向图（18,713 节点、26,461 条有向边），按真实方向检查 OD 可达性。最大强连通分量仅保留为对照审计；在该分量内重新映射会改变 4,233 条评价请求的端点。该决定选定数据实例，保留本节原有算法约定。
- 统一长度 m、速度 m/s；14.9mph 车辆、170mph 航空；120mile 航线长度上限。
- 复用用户已提供并批准的固定静态航空网络文件 `air_routes_manhattan.json` 和站点坐标 `vertiports_manhattan.json`，导入前审计 10 站/60 有向航线，不自动补反向；保存哈希。作者原拓扑无法唯一恢复，这一差异必须报告。
- 每处起降场映射到道路节点，建立地空双向零时长转换；跨不同地理位置不得零时间瞬移。
- TLC OD 经纬度映射到最终道路图的最近可用道路节点；地图匹配本身不模拟乘客上车前步行，保留原经纬度及匹配距离审计。
- 整体 O–D 直线距离小于 500m 的请求在数据处理阶段过滤。
- 需要服务的长请求中，任一短于500m的真实地面接驳段改为辅助步行：按直线距离/可配置步行速度算时间，不需车、不给 HALNS 增加正式运输段数。真实步行只能在其所选方案接受且乘客就绪后启动。
- 统一有向最短路服务。M4 可只读取最短耗时，真正提交的车任务再生成完整边路径；不得产生计划与实际时间不一致。
- 航班固定起降和容量，3min间隔；初始起飞相位固定可配置。**不模拟航空器实体周转**。
- 不能断言老配置与作者 Fig.7 完全一致，报告明示局限。

## D012 — 数据、预热、结束边界

- 用户提供 `nyc_2013_05_04_to_05_08.csv`；预热 2013-05-04 22:00–2013-05-05 00:00，评价窗口 `[2013-05-05 00:00,2013-05-07 00:00)`，尾部接收 5 月7日新请求直到评价请求终结。
- 时间字段取历史 TLC 接客时刻作模拟请求到达；保留原始时间戳，**不随机打散整分钟集中到达**（未来敏感性实验另论）。
- 清洗：必要时间、坐标、曼哈顿区域、人数 1–4、全程>=500m、道路映射/可达性；历史出租车里程和历史时长异常先标记不自动删除。人数>4过滤，**不拆分为两条请求**。
- 每日每自然小时从合格请求中无放回抽取约5%，保留真实秒数；不要每10秒做抽样取整。按小时配额可用最大小数余数法保证总体接近/恰为清洗后总量*5%的舍入数；固定种子和样本清单。
- 预热、正式评价、5月7日延续应使用一致的需求抽样强度；三种 cohort 由**请求原始提交时刻**标识。
- 预热从22:00真实接收请求、运行 M1–M5、执行事件；00:00 不重置状态；5/5–5/6 连续两天不重置。
- 评价窗口结束后新请求不计入正式指标，但继续参与正常资源竞争；正式评价请求允许在5/7 00:00后、原始7分钟时限内被合法接受。
- 停止新增延续请求条件：所有正式评价请求已 `COMPLETED` 或 `EXPIRED_UNSERVED`；最终接受=完成，否则实验 ERROR。
- 车辆在有效道路节点随机初始化，车队 50/100/150 使用同种子嵌套初始化位置清单；论文五次重复的详细种子/对照设计暂放后续。

## D013 — 正式实验指标与对照

- 服务率 = 评价窗口内**唯一有效抽样请求**中合法接受并最终完成的数量 / 评价样本数；完整实验最终接受与完成必须相同。
- 平均绕行 = 已完成评价请求 `actual_final_dropoff - (original_request_time+direct_road_shortest_time)` 的平均（分钟）；允许负值，不截断。
- 模式统计 SHRS/MHRS/RS-UAM；同时记录等待、总旅行时长、M4/整批耗时。
- 主要组：50/100/150 车；优先 RS-UAM 与论文 RS（禁UAM且禁多跳），再 `noD,noA,noS,OP,noR`；旧 Simonetto RS(FO) 稍后接入，要求同样输入口径。
- 控制输入网络、需求、车队位置和参数；论文报告的服务率只作为对照参考，不是代码优化损失函数。
- 5%按小时抽样，保留原始分钟集中；随机打散未来仅作为敏感性实验，第一阶段不实施。

## D014 — 测试、计时、日志及权限

- 四层验收：单元→独立对照→跨模块→端到端；分解/完整解码一致；M1穷举、M3全扫描、M5微型整数流穷举。
- `ScheduleValidator` 是独立调度验收器，与整个测试体系不同；开发期10/30min真实数据验证默认每批执行，**正式五小时和两天关闭**；低开销的车辆、航班、承诺/时间状态检查仍常开。
- 验证失败或运行时硬约束不变量失败：**立刻标记 FAILED、保存现场和非零退出**；不能当作正常搜索失败使用 fallback。
- M4 同时记录 Wall=perf_counter 和 CPU=process_time；正式 M4预算按 Wall，CPU预算作为用户手动启动的短窗口对照实验，附额外墙钟安全上限。
- 记录每批 M4 与整批耗时、均值/p95/p99/max/超时、候选数、修复次数及任务分量规模。
- 真实数据10/30分钟、五小时及两天仿真**全部由用户手动命令行启动**；Codex仅可运行快速纯单元/人工小图测试。
- 控制台每批输出摘要；每次运行独立目录输出详细 `summary, batches, requests, vehicle_events, flight_usage, performance, audit, manifest, config, console`。
- 四阶段：微型→10/30min→五小时→48小时，前阶段通过才能放行后阶段。

## D015 — 工程交接确认

- 工作区 `RS-UAM-Reproduction`，源码直接为 `src/`，每个核心 M1–M5 分目录；不使用原来的 `uam/` 文件夹。
- 由用户将原始 TLC 与 OSM 放置项目根目录；Codex P0 识别、验证、归档和输出哈希；航空拓扑可从旧工程**批准的静态数据文件**只读导入，不读取旧调度代码。
