# 仍须由数据和实施阶段核验的项目（不是授权 Codex 自选算法）

## P0 阻塞项

1. **OSM 原始文件未在本交接包中。** 用户放根目录后先检查格式、节点/边属性、OSM提取日期、空间范围、单向边和长度。若有多个OSM源或不能可靠解释，报告情况再处理。
2. **旧工程固定航空拓扑未附在包内。** 可以只读精确定位批准的静态航线文件（可能叫 `air_routes_manhattan_fig7a_approx.json`），记录SHA256，核对10站/60条**有向**航线、端点和转乘点；不许复制旧模拟算法代码，也不可从图像自行画60条边替代。
3. 论文作者原始道路OSM版本、航线邻接矩阵、抽样种子、车辆初始位置并未公开；必须在复现报告里标为“实验实例差异”，不能声称严格同例。
4. 如无法完成道路强连通性审计或服务范围影响统计，不应直接删去大片路网。强连通和弱连通须明确区分。

## 实施时必须先提出唯一方案、以测试证明的微细节

1. **秒级事件量化：** 原始道路边权 float 秒；每条边逐一向上取整易累积误差。P1 必须给出“路由预测/道路边事件”完全一致的实现和微型样例，若与整数秒限制冲突，先报告。
2. **同刻事件优先级：** 例如某航班10:10:00起飞、乘客恰在10:10:00到达；需要事先写清“起飞时刻乘客是否可以登机”的约定及测试。按D001–D003“到达不晚于起飞且零换乘”的约定可设包含等号，若实际实现冲突先报告。
3. **M4论文的“first four operators”：** Table3顺序使insert看似也受Type3限制；结合用户D004已经批准的“未执行顺序可重排”，默认insert不直接选择Type3元素，cut/swap/reverse可合法重排后缀；不要以此名义更换Type3分配。
4. **方案内部辅助步行：** 论文未描述步行任务编码。可采用无运力、明确前序时间的辅助连接，但若出现“被接受之前实际需要步行才能赶上航班”的矛盾，应报告实际小例，不允许虚构提前步行。
5. **当前批次已有承诺与新的 M3 截断：** Type3锁定的资源不因新M3截断被剔除；也不能偷偷算作Type1/2的8个自由名额。
6. **M5求解失败：** 若是临时无可用再平衡方案，跳过再平衡；若是严重模型/数据错误则失败，不能混淆。
7. **实验尾部存在超长已接受服务：** 停止引入非评价请求与清空已承诺任务分开；不得因为未触及“7分钟”就强制截断。
