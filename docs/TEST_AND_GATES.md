# D001–D014 测试协议、独立对照与阶段门槛

**绝不把论文结果分数作为单元测试的预期值。** 正确性、算法忠实性与实验接近程度各自验收。
轻量人工图、单元测试可由Codex主动运行；任何真实数据10/30分钟/5小时/48小时模拟由用户手动启动。

## A. 四层验证

1. **Unit：** 数据对象、公式、任务编码、约束边界。
2. **Oracle/Reference：** M1穷举 vs Pulse，M3全扫描 vs R-tree，M4合法解完整 vs 分解，M5小流量枚举 vs Gurobi。
3. **Integration：** 从请求进入到M1/M3/M4/M5，事件与资源状态都一致。
4. **End-to-end：** 真实窗口预热、尾部竞争、累计统计、正确性/性能输出。

`ScheduleValidator`只是独立核对**一份完整调度计划**的模块，不等于整个正确性测试体系。
短窗口调试时每批启用；正式5/48小时默认关闭以免额外消耗CPU，**基本运行时不变量必须开启**。

## B. 按模块微型测试（至少以下行为，不拘泥测试函数数量）

### T-CORE：时间、承诺和任务状态

- CORE01 10:00:00→10:00:17道路边，在10:00:10位置进度为10/17，不因批次边界改变时刻。
- CORE02 在10:00:20调用`advance_to()`，按10:00:17先到B、10:00:18接客、10:00:20取快照，接客不被错误登记为20秒。
- CORE03 B节点后道路边移动应从17秒起计，不能损失3秒。
- CORE04 新请求到达10:00:18只能从10:00:20批次参与，不允许预知。
- CORE05 当前道路边不可中断；更新计划只能在边终点接续。
- CORE06 被旧版本替代的未来计划事件无效；已执行事件和当前边完成事件仍有效。
- CORE07 已接受未上车/已上车/已转机的Type3资源和方案保持冻结，允许合法地面任务顺序更新。
- CORE08 既有承诺在候选解中被破坏时丢弃候选，真实状态不受影响。
- CORE09 没有更优合法候选或求解超时，回退当前批次安全基线。
- CORE10 新旧批次重算目标，不能拿前轮分数与本轮分数直接比较。
- CORE11 接客前后、下客前后容量和乘客位置准确；不出现同人同时在车与航班。
- CORE12 固定航班准时，不等待迟到乘客；不同乘客同航班的资源关联不是时序死锁。

- CORE14 最终送达不得超过 `t_request+direct_road_time+420s`，首次接客不得超过`t_request+420s`。
- CORE15 原始时间戳及Tolerance跨所有批次不重置。
- CORE16 规划/实际同一路段的秒级时间精度一致；小数道路边耗时不因逐边粗舍入累计偏差。

### T-M4：编码、解码、HALNS

- M401 一段Car的重复请求2次，Car-Flight-Car重复5次；出现次序映射合法任务。
- M402 对Type3只映射剩余任务，已执行前缀不被误认成新接客。
- M403 `p_exchange`新方案增删请求重复次数，其他请求的相对顺序不改变，统一RNG确定。
- M404 `v_exchange(m=1)`只改合法Type1/2运力且固定Type3。
- M405 `restart`重新纳入先前只在**候选编码**中被删除、当前仍有效的Type1/2。
- M406 `insert/cut/swap/reverse`产出的候选可按当前出现次序重新解释；硬约束仍由解码验证。
- M407 Type1/2不可行删除**完整方案全任务**后重算，不遗留航班席位。
- M408 Type3不可行整个候选无效，前轮真实承诺保持。
- M409 随机初始解低分但合法时，best先保存更高分安全基础解，current可从低分随机解探索。
- M410 SA改善current直接接受；低于current按exp((new-current)/T)；不可行永不接受。
- M411 温度T0=70|R|，内循环连续T*=0.7；外层2|R|、内层25。
- M412 初始算子同分且正；跨批继承；theta=.1、psi=.4、omega=.02；权重正下限；回报不是任何SA接受都奖励。
- M413 f1包含当前候选全部满足请求(含Type3)，全局接受数不跨批重复；f2用原始提交至最终送达的浮点分钟。
- M414 10分钟单请求目标分应取70-.3×10=67，而非70-.3×600=-110。
- M415 满载释放、乘客前序未完成、航班错过、车辆绕行超时的精准拒绝。
- M416 任务网络同车/同请求/同航班关系与弱分量正确；航班共享双向不当作时间有向循环。
- M417 对固定合法编码，完整/分量解码器的可行性、所有任务时刻、容量、资源和f1/f2/v一致。
- M418 在需要修复时固定冲突处理顺序或把差异记账，不伪称任意删除顺序结果一定相同。
- M419 noD不再做分量级搜索，不只是切换最终decode函数。
- M420 Wall与CPU计时同时记录；只有Wall用于正式截止，截止时返回最高分已完成合法解。
- M421 随机种子对所有算子、变更、接受判定可复现，且不使用不可追踪全局RNG。
- M422 小型实例穷举所有合法分配可计算最优上界，HALNS目标不得超过正确的全局最优。

- M501 三种供需情况分别满足式(26)–(31)。
- M502 决策流是非负整数，目标按网格中心球面距离，微型流问题与穷举最优解相同。
- M503 单个三人请求只算一个网格需求，不因为5个候选方案重复计数。
- M504 x_ii表示当地保留，不发生车辆移动。
- M505 具体车只被一次选入流，当前位置到目标可达节点的行驶按实际道路方向。
- M506 执行承诺接客任务的车辆不得被M5抢走；再平衡车可由新乘客合法抢占。
- M507 抢占时必须完成当前路边；连续批次不反复重配正在再平衡的车。

## C. 故障处理语义

| 现象 | 正确处理 |
|---|---|
| HALNS随机候选不可行 | 继续搜索或修复；**不得修改真实状态** |
| HALNS算力预算到期 | 使用已找到best/安全基础解；正常结束该批 |
| M5局部无新可行再平衡 | 不新增再平衡；保留M4成果 |
| `ScheduleValidator`判定提交计划不合法 | **FAILED、保存快照、退出** |
| 运行时容量/时序/承诺不变量违反 | **FAILED、保存快照、退出** |
| 评价请求最终已接受但未完成 | **FAILED、不能输出正常服务率** |
| 原始数据格式/航线缺失 | P0报告输入缺口，不自行造数据 |
