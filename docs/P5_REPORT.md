## 调用契约与模块边界

```python
from src.common.config import load_config
from src.m5 import M5Config, M5Rebalancer

settings = M5Config.from_config(load_config("configs/base.yaml"))
rebalancer = M5Rebalancer(road, settings)
plan = rebalancer.propose(post_m4_snapshot, unmet_request_ids, available_vehicle_ids)
```

`road` 是 P1 的统一 `RoadRouter`。快照来自已确认乘客调度之后的同一仿真，含批次秒、道路和状态版本、车辆、请求、任务与航班。调用方传入本批未满足请求 ID 和可运营车辆 ID，M5 依据快照复核状态。P4-B 的 `M4HALNS.solve(...).best_solution` 是冻结批次上计算的候选，调用方应先完成乘客调度提交，再采集 M5 输入。

`RebalancePlan` 为冻结对象，容器使用元组或只读映射。返回供给、需求、覆盖、未覆盖、Gurobi 状态与非零流量、具体移动、本地保留车辆、多余车辆、路网与状态版本、各层耗时和失败信息。每条 `VehicleMove` 含车辆 ID、起终网格、路网起终节点、物理有向边序列、计划出发秒、连续到达秒、整数事件秒、道路距离与行驶时长。M5 只读取快照。乘客接受和航班锁座由已确认的 M4 调度及 P1 服务状态负责。

## 网格、统计与成本

- **D010、D011，PAPER §5.4、Algorithm 5。** 在固定参考点（经度 −74.0°，纬度 40.75°）建立局部等距圆柱投影，沿 40.75°N 使用真实比例尺。东向坐标为 \(R\cos\phi_0(\lambda-\lambda_0)\)，北向为 \(R(\phi-\phi_0)\)，角差以弧度给出。沿用 `src/common/geo.py` 的球半径 6,371,009 m。默认边长 1,000 m，可用 `m5.grid_size_m` 调整。固定参考点和局部投影是 P5 工程选择。
- ID 为 `(floor(x/L), floor(y/L))`。西、南边闭合，东、北边开放，含负坐标时规则相同。覆盖范围取全路网节点的网格索引矩形。只缓存实际道路节点索引和入口序列，矩形内空网格仍有 ID 和中心。网格中心逆投影为经纬度后按大圆距离求运输成本，对角线成本精确为零。
- P0 锁定网络通过 `PreparedNetwork.from_config` 只读加载检查。18,713 个道路节点落在 81 格，81 格有至少一个可驶入节点。列号 −2 至 7、行号 −6 至 14，矩形共 210 格，其中 129 格无路网节点。正式输入沿用 26,461 条有向道路边、10 站和 60 条有向航线，WARMUP / EVALUATION / TAIL 为 2,490 / 33,565 / 18,055。论文 §6.1 的道路网络为 6,843 节点、12,601 条边，按 D011 保留本项目批准的完整有向网络。
- **供给。** 仅统计可运营名单中停在节点上、无载客、无当前边和剩余道路程序、无预约动作、无再平衡目标，且无未完成 `PICKUP` / `DROPOFF` 承诺的唯一车辆。已承诺但预约尚未写入动作列表的车辆仍被排除。停运及不可用车辆由调用方从允许名单中排除。P1 暂无停运状态字段。
- **需求。** 按请求 ID 去重，取快照中已到达、仍为 `WAITING`、没有已接受方案且首接与终达截止尚未越过的请求。按地图匹配后的原始请求起点网格计数。每个唯一请求计 1，含三人乘客组或多个 M1 候选方案。已接受 Type3、终态及未来请求不计。需求和可执行计划覆盖单位供批次统计，服务率继续按 D013 的唯一请求合法接受且最终完成计算。

## 运输模型与求解状态

**D010，PAPER §5.4 式 (25)–(31)。** 以非负整数 `x[i,j]` 最小化各网格中心大圆成本与流量的乘积之和。零供给行、零需求列的流量由原约束强制为零，模型只建立活跃行列的笛卡尔积。

| 模型 | 条件 | 源网格 | 目标网格 |
|---|---|---|---|
| `SHORTAGE` | 总供给小于总需求 | 分配量等于供给，式 (26) | 流入量不超过需求，式 (27) |
| `SURPLUS` | 总供给大于总需求 | 分配量不超过供给，式 (28) | 流入量等于需求，式 (29) |
| `BALANCED` | 总供给等于总需求 | 分配量等于供给，式 (30) | 流入量等于需求，式 (31) |

按网格 ID 稳定建模，Gurobi 单线程和固定种子，同一版本、参数和输入下可复验，并列时沿用确定性的求解结果。保持式 (25) 原目标。默认种子为 0，可用 `m5.gurobi.seed` 指定。测试将独立的 `m5.gurobi.time_limit_s` 设为 2 s，默认未为 M5 增设时间限额。仅接收 `OPTIMAL`，同时检查 Gurobi 的约束和边界残差、每个原始变量的整数误差、整数化后的行列约束，以及重算目标值。

`gurobipy` 和 Gurobi 优化器均为 **12.0.3**，本机学术许可证成功启用，显示到期日 2027-04-14。环境微型整数规划 `min x`、`x >= 2` 实测状态码 2（`OPTIMAL`），解 `x=2`、目标值 2。论文 §6 使用 Gurobi 10.0.3，本次保留现有兼容版本。未启用其他求解器。

## 配车、道路执行与抢占

**D003、D004、D009、D010、D011。** 跨格流量保持 Gurobi 给定的整数配额。目的格入口必须是格内已有的带入边道路节点。对每辆车先按距投影中心的距离选最近且有向可达的入口，中心距离并列时沿用 P1 稳定节点 ID。每个目标格的车辆候选按道路最短时间、车辆 ID 排序。按源格、目标格和配额顺序匹配。若首选车需要留给另一格，使用增广匹配重分配具体车辆，以找到满足所有固定配额的完整匹配。车辆匹配无需另求一个全局道路时长目标。先落实有可达性约束的跨格配额，再按车辆 ID 在剩余车中填足 `x[i,i]`，剩余车辆保持空闲。

选中车辆使用 P1 同一有向路由器重建最短物理边序列。路程按边长累加、时间按 P1 Decimal 秒精确累加，最终事件时刻为绝对连续到达时刻向上取整。人工样例中两条边各用 1.3、1.2 s，从第 0 秒出发，连续到达为 2.5 s，P1 在第 3 秒完成。直达的 10 s 道路边存在时仍采用该 2.5 s 的合法有向路径。同格保留不生成监测到的道路移动。

`Simulator.commit_rebalance(candidate)` 是 P1 的单车安装接口。它检查版本、车辆确实空闲以及完整有向路径，再设置 `VehicleState.rebalance_target` 并使用 P1 现有路线版本和事件队列。执行期间下一批 M5 排除该车。车辆抵达最后一条边的终点后清除目标，恢复普通空闲。M3 仍可检索在途再平衡车辆，M4 从其当前边终点及精确结束时刻试算接客；合法改派通过 P1 `commit_route` 替换后续路线，清除再平衡目标。人工回放中，模拟第 2 秒发起改派，车辆保留第 5.5 秒物理到达的当前边，第 6 秒接客、第 8 秒完成投送，原再平衡剩余边未执行。

## 状态、诊断和 noR

| 状态 | 行为 |
|---|---|
| `READY` | 完整配车及路径通过。计划包含本地保留和多余车辆，可能仅有本地保留且没有移动。 |
| `SKIPPED` | `DISABLED`、`NO_SUPPLY` 或 `NO_DEMAND`。不调用 Gurobi，返回空移动。 |
| `SOLVER_FAILED` | 没有通过求解状态要求。记录 Gurobi 状态码、错误码或异常描述，例如超时、无解、许可证失败。无移动或最佳整数流发布。 |
| `UNEXECUTABLE` | 最优整数流保留供复核。记录无法落实的源格、目标格、配额、候选车辆、入口、可达车选项及冲突配额。整份移动和本地保留结果置空，全部有效空闲车仍可用。 |
| `RebalanceInvariantError` | 声称最优却未通过残差检查，或已判定可达的路径违反物理不变量。写入 `outputs/p5_failures/failure-*.json`，内含 `FAILED`、原因、快照和求解诊断，并向调用方抛异常。 |

本批可执行计划覆盖量包括可执行跨格移动及同格保留的流量，未覆盖量为需求减去该覆盖量。失败和跳过时覆盖为零，原需求全部保留。现存 M4 承诺、道路运行和座位预订均保留。`m5.enabled: false` 启用 D013 的 noR，保留供需统计并跳过求解，已在执行的路线继续由当前状态管理。

## P6 接口和工程补充

- `plan.candidates` 中所有单车记录绑定同一批次、同一快照版本。P6 应使用同一仿真轨迹核对时刻、图版本、快照版本和车辆合法性，先验证全计划，再一次发布全部移动。逐车调用目前的 `commit_rebalance` 会更新版本并使其余记录过期，因此该接口用于单车操作和 P5 人工回放。
- P6 负责 M4 乘客任务与航班承诺的整批提交、提交后的有效状态采集、M5 滚动调用、运营名单、整批再平衡发布、批次统计和 CLI。没有被 M4 选中的在途再平衡车辆应继续原路线。正常跳过、未证明最优或不可执行可保留既有调度继续，`RebalanceInvariantError` 由正式入口标记运行失败并非零退出。
- 工程补充包括固定本地投影、半开边界、以地图匹配起点统计需求、车与入口的稳定选择、完整配额匹配及无法落实即整份拒绝。这些细节用于实现 D004、D010、D011，论文 Algorithm 5 未给出相同粒度的规则。对于某个最优整数流无法在现实路网落实的情形，保留该整数流及失败诊断以供排查。
