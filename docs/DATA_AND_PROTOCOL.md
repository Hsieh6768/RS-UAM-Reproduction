# 数据处理、实验口径、预热和尾部延续

## 1. 原始输入和运行环境

在 PyCharm Terminal（PowerShell）按命令手册激活现有 Conda `ridesharing`，使用 Python **3.9.25**。

- TLC CSV：`nyc_2013_05_04_to_05_08.csv`。当前已知原始表头：
  `tpep_pickup_datetime,tpep_dropoff_datetime,pickup_longitude,pickup_latitude,dropoff_longitude,dropoff_latitude,passenger_count,trip_distance`。
- OSM：根目录 `new-york-190101.osm.pbf` 为 OSM PBF 快照。正式 Manhattan 边界为同一快照中的行政区关系 `8398124`。用原始 OSM 节点 ID 和 way 节点序列构建车行图，保留有向性、平行边和未简化的长度。
- 论文 PDF 已在`references/paper.pdf`。
- 固定航线和站点：根目录 `air_routes_manhattan.json` 是用户批准的有向边表，`vertiports_manhattan.json` 是用户补充的 WGS84 坐标表。按 ID 连接两个文件，保留全部方向。

P0 计算根目录文件哈希，核对归档目标无内容冲突，再复制并验证。来源、字节数、SHA256 和归档路径记录于 `data/source_manifest.json`。预处理仅读取归档副本。

## 2. 数据预处理顺序

1. 读取CSV、验证八列及可解析时间；仅使用纽约当地日历时间，记录解析失败行。
2. 时段：预热`2013-05-04 22:00`至`2013-05-05 00:00`；正式评价`[2013-05-05 00:00,2013-05-07 00:00)`；尾部从5/7 00:00继续读取。
3. 坐标校验：缺失、零经纬度、非法范围拒绝；按**实际固定曼哈顿服务区域**要求起点和终点均在服务范围。不能用开发时随意的经纬度框作为论文最终边界且不披露。
4. 人数必须在1到4之间。**五人以上删除，禁止拆分为两个请求**；0、负数、缺失删除并分类计数。
5. 原始 OD 直线距离 `<500m` 的整条请求过滤；不把它计为满足的拼车服务。
6. 道路图连通性与质量审计后，起终点映射至最终驾驶路网最近**可用道路节点**，不因GPS→道路节点的地图匹配额外增加步行时间。
7. 对映射误差、映射后同点、道路不可达、起终点的原始与映射距离进行审计；不可用输入必须有显式拒绝原因。禁止地图匹配到数公里外而不报异常。
8. 原出租车到达时间、历史 trip_distance / 历史平均速度仅用于审计。除字段无法解析使任务无法生成外，**不能因原始里程为0或历史时长异常自动过滤**。
9. 生成清洗后请求总体与逐项可核对的数据账本；所有排除原因可重叠，但最终要有 mutually exclusive 的主要删除原因，确保 `source = kept + removed`。
10. 分层抽样见下一节，输出固定、不可变样本文件和SHA256。

P0 请求 ID 为从 1 开始的原始 CSV 数据记录序号。边界使用覆盖判断（含边界点）。直线距离和最近节点误差使用半径 6,371,009 米的球面距离。原始里程和送达时刻保留，历史时长超过 24 小时、里程无效或非正、推算平均速度超过 100 mph 等仅做审计标记。用户批准保留完整有向图（18,713 节点、26,461 条边），按有向可达性筛除映射后不可达的 OD。最大强连通分量为对照审计。

请求产物的 `historical_trip_flags` 为可组合标记值：1 为历史送达时间解析失败，2 为历史时长非正，4 为历史时长超过 24 小时，8 为历史里程无效，16 为历史里程非正，32 为推算历史平均速度超过 100 mph。0 表示上述标记均未触发。

## 3. 5%分层随机抽样

D016 的 `scc100` 分支在上述基础过滤后对全部原始候选重新映射。新图由完整有向图诱导取得，O、D 任一球面吸附误差 >100 m 即排除。输出 `mapped_population.csv.gz` 保留基础合格行、原始坐标、两端节点/误差和最终资格，`sampling_by_hour.csv` 记录逐层配额。新样本的入口为 `data/processed/p0_scc100/requests/manifest.json`。历史样本沿用原清单。比较服务率时须同时给出实例、评价窗口、分母和请求身份。

- 按`日期 × 自然小时`分层，**同一小时内部无放回均匀随机抽取约5%**，保留原始秒精度与排序。
- 不对每10秒批次分别取5%、不把整分钟请求人工打散、不将请求到达时间改成均匀分布。
- 实现采用**最大小数余数法**，对每个 cohort 分别计算 `round(0.05 * N_eligible)`（正中取偶），同余数按日期小时先后分配。小时内基于原始记录序号和种子 `20130505` 无放回抽样，保留源时间戳，输出实际每小时和总体抽样率。
- 预热/尾部按相同约5%需求抽样强度，但按各自cohort单独记录。
- 论文报告35213条是参考值，**不强制选35213**；通过修改服务区边界或人为删请求凑数属错误。
- 不同车队规模、不同算法变体使用同一`evaluation_sample.sha256`，无需重新抽样。
- 正式样本由 `data/processed/p0_requests/manifest.json` 的 `official_samples` 指定。沿用已核验 CSV 的原文件名和 SHA256，样本文件名中的 `candidate` 记录其生成阶段。后续运行以正式清单中的条目和哈希定位样本。
- 实际统计数据中约50%的请求时间秒数为00；保留此特征，记录按10秒请求数量分布。

## 4. 请求字段与论文参数

- `request_time` 使用TLC的原始历史接客时刻作为模拟请求提交/最早可接客时刻（工程假设）。
- `origin`, `destination` 为映射后有向道路节点，原始GPS只留审计。
- 人数使用`passenger_count`，允许模式`car,evtol`，拼车意愿默认允许（模型支持，但统一偏好非论文明确逐条采样）。
- 最大两次换乘，正式运力行程段最多三段；K=5。
- `pickup_deadline = request_time + 420s`；`dropoff_deadline = request_time + shortest_road_time(o,d) + 420s`。
- 距离短于500m的**多段方案内部地面接驳段**是有耗时、无需车辆容量的辅助步行连接；按原始空间端点的直线距离与可配置速度(初始假设1.4m/s)计算；步行必须在**方案实际接受**后才执行，不占正式三段上限。不能提前利用未来方案预知乘客步行。
- 历史出租车实际行驶时长/送达时间不参与新请求的最大可容忍送达时间推导。

## 5. 预热、评价和尾部竞争

- 2013-05-04 22:00：在有效路网随机初始化车辆，状态IDLE；运行真实调度和车辆/乘客事件，**不是两小时随机位移**。
- 2013-05-05 00:00：仅切换指标cohort起点，不重置车辆、乘客、航班、请求历史、M4算子评分。
- 正式窗口：5/5–5/6连续48小时，5/6午夜不重置车队。
- 5/7 00:00后：继续以相同抽样强度引入新请求作为`TAIL` cohort参与正常竞争，直到**所有EVAL请求已终结**（COMPLETED或EXPIRED_UNSERVED）；尾部请求自身不进EVAL分母/分子。
- 评价窗口内最后1秒到达的请求可在5/7 00:00后原始7分钟容忍范围内被接受，必须计入 EVAL 成功。不能午夜结算为“未满足”。
- EVAL请求全终结后停止引入TAIL请求，处理已有承诺任务至完成；如果资源、状态或事件处理出现不变量错误，实验失败；不是以7分钟后硬性停止全部车辆。
- 接受意味着已为所选方案的全部运力正式作出合法承诺；最终被接受的EVAL必须全部COMPLETED，否则`FAILED`。

## 6. 抽样/车队/算法对照

- 主实验50/100/150车，使用完全相同的EVAL请求集合和固定航空网络。
- 同次重复试验先生成150车位置序列，取前50/100/150实现嵌套车辆初态；预热需分别真实运行。
- 预热与EVAL请求样本固定，不因实验种子变化重复抽样。
- 论文五次独立运行；具体种子组织由后续实际实验脚本确定，但不准临时挑选最优种子替代均值。
- 不同变体RS-UAM/RS/noD/noA/noS/OP/noR必须保持输入实例一致。

## 7. 指标口径

\[
SR = N_{\mathrm{EVAL,accepted\ and\ completed}}/N_{\mathrm{EVAL,valid}}.
\]

\[
\overline{detour} = \frac{1}{N_{\mathrm{EVAL,completed}}}
\sum_{i\in\mathrm{EVAL,completed}}\big(t^{actual}_{final,i} - [t^r_i+st(G^r,o_i,d_i)]\big)
\]

- 服务率以唯一请求为单位；已接受请求可跨批次重复参与目标函数但在全局计数一次。
- 绕行单位分钟；允许负值，不截断；含完整等候和步行。
- 已接受未完成只可能是**尚在进行中的中间态**。最终`accepted != completed`应中止而非输出正常成功报告。
- 性能报告同时给出每批M4墙钟+CPU和整批墙钟；M4墙钟预算不等于整个系统满足论文批次求解预算。
- 供给、航班容量、请求状态应可由原始事件复核。
